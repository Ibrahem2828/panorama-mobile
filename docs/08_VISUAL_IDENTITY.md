# الهوية البصرية

## قيم العلامة

- أكاديمية.
- عربية.
- موثوقة.
- واضحة.
- شبابية دون مبالغة.
- عملية وسريعة.

## شخصية العلامة

Panorama يجب أن يشعر الطالب بأنه منظم ومساعد، لا رسمي بشكل ثقيل ولا ترفيهي بشكل زائد. النبرة البصرية يجب أن تكون حديثة ونظيفة، مع مساحات بيضاء جيدة وبطاقات واضحة.

## الألوان

| الاستخدام        | اللون     |
| ---------------- | --------- |
| Primary Navy     | `#001B72` |
| Secondary Purple | `#3510A3` |
| Accent Burgundy  | `#9B004B` |
| Background       | `#F8F9FC` |
| Surface          | `#FFFFFF` |
| Text Primary     | `#101828` |
| Text Secondary   | `#667085` |
| Border           | `#E4E7EC` |
| Success          | `#17A56B` |
| Warning          | `#F5A524` |
| Error            | `#D93025` |

لا يجب استخدام ألوان عشوائية خارج هذا النظام إلا عند إضافة token موثق لاحقا.

## الخطوط

- الخط الأساسي المقترح: `Tajawal`.
- بديل تقني: `IBM Plex Sans Arabic`.
- بديل للعناوين: `Cairo`.

لا يتم تحميل الخطوط في Phase 0. القرار موثق فقط، والتنفيذ يتم في مرحلة إنشاء المشروع.

## أسلوب الأزرار

- الزر الأساسي يستخدم Primary Navy وخط أبيض.
- الزر الثانوي يستخدم سطحا أبيض وحدودا واضحة.
- أزرار الخطر تستخدم Error فقط عند وجود إجراء فعلي خطر.
- النص داخل الأزرار قصير ومباشر.
- يجب أن تكون مساحة اللمس مناسبة للموبايل.

## أسلوب البطاقات

- بطاقات واضحة بخلفية Surface وحدود Border.
- حواف ناعمة دون مبالغة.
- محتوى البطاقة قابل للمسح السريع: عنوان، وصف قصير، حالة، وإجراء عند الحاجة.
- لا تستخدم البطاقات كزخرفة فقط.

## أسلوب الحقول

- الحقول كبيرة بما يكفي للمس.
- رسائل الخطأ تظهر تحت الحقل بالعربية.
- الحالات: عادي، تركيز، خطأ، معطل.
- Placeholder لا يستبدل Label عند الحاجة إلى وضوح.

## الأيقونات

- أيقونات خطية بسيطة.
- استخدام مجموعة موحدة لاحقا مثل lucide أو ما يناسب React Native.
- الأيقونات الاتجاهية يجب أن تراعي RTL.
- لا تستخدم أيقونات مليئة بألوان متعددة خارج النظام.

## حالات النجاح والخطأ والتحذير

- Success للعمليات المكتملة مثل إرسال طلب توثيق أو جاهزية طباعة.
- Warning للحالات المعلقة أو التي تحتاج انتباها.
- Error للأخطاء والفشل والإجراءات المرفوضة.
- يجب أن تجمع الحالة بين اللون والنص، ولا تعتمد على اللون وحده.

## Empty States

- رسالة قصيرة توضح غياب البيانات.
- إجراء واحد واضح عند وجود خطوة منطقية.
- لا تستخدم رسومات كبيرة تؤخر فهم الشاشة.

## Loading Skeletons

- تستخدم في القوائم والبطاقات.
- يجب أن تشبه شكل المحتوى النهائي.
- لا تظهر مؤشرات تحميل عامة عندما يمكن استخدام Skeleton أفضل.

## Splash وOnboarding

- Splash يعرض العلامة أو الشعار بشكل بسيط.
- Onboarding قصير ويركز على القيمة الأساسية: المواد، الغروبات، الملفات، والطباعة.
- لا يتحول Onboarding إلى شرح طويل.

## App Icon وLogo Usage

- الأيقونة يجب أن تكون مبسطة وقابلة للقراءة بحجم صغير.
- الشعار يستخدم على Splash ومواضع محدودة.
- لا يكرر الشعار داخل كل شاشة دون حاجة.

## تبسيط نسخة الأيقونة

يفضل إعداد نسخة مختصرة من الهوية لاستخدامها كـ App Icon، لأن تفاصيل الشعار الكبيرة تفقد وضوحها في أحجام صغيرة. يجب اختبار الأيقونة على خلفيات وأحجام مختلفة قبل الإنتاج.
