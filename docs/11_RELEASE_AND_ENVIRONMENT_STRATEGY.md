# استراتيجية البيئات والإصدارات

## البيئات

| البيئة      | الغرض                                      | ملاحظات                                 |
| ----------- | ------------------------------------------ | --------------------------------------- |
| development | تطوير محلي وتجارب يومية.                   | يمكن استخدام API محلي أو staging.       |
| preview     | نسخة اختبار داخلية أو مع مستخدمين محدودين. | يجب أن تكون قريبة من الإنتاج.           |
| production  | النسخة المنشورة للمستخدمين.                | لا تحتوي على dev URLs أو إعدادات مؤقتة. |

## المتغيرات المتوقعة

```txt
API_BASE_URL
WS_BASE_URL
APP_ENV
```

يجب عدم وضع أسرار داخل هذه المتغيرات في الكود. أي قيمة حساسة يجب أن تدار بطريقة آمنة حسب بيئة البناء.

## البناء عبر EAS Build

في مرحلة التنفيذ، يكون البناء عبر EAS Build:

- preview APK لاختبار Android الداخلي.
- production AAB للنشر على Google Play.

iOS يمكن تأجيله إذا كان التركيز الأول Android، لكن يجب عدم اتخاذ قرارات تمنع دعمه لاحقا.

## متطلبات الإنتاج

- App Icon نهائية ومختبرة بأحجام مختلفة.
- Splash متوافقة مع الهوية.
- Versioning واضح.
- Privacy Policy.
- Terms.
- Store screenshots.
- Google Play Data Safety.
- عدم وجود dev URLs في production build.
- اختبار APK قبل production.
- Changelog لكل إصدار.

## قواعد الإصدار

- لا يصدر build إنتاجي إذا كانت البيئة تشير إلى development أو preview.
- أي تغيير في API contract يجب أن يوثق قبل الإصدار.
- أي ميزة غير مكتملة يجب أن تكون مخفية من الباك إند أو feature flag، لا بنصف تنفيذ ظاهر.
- يجب اختبار تدفقات الدخول، التوثيق، فتح الملفات، الطباعة، والمحادثة قبل أي إصدار.

## مراقبة ما بعد الإصدار

- تجهيز مراقبة أخطاء لاحقا دون إرسال بيانات حساسة.
- متابعة حالات فشل تسجيل الدخول وفتح الملفات وطلبات الطباعة.
- الاحتفاظ بسجل تغييرات مختصر ومفهوم لكل نسخة.
